# 05 · 制备：从文献/资料到学术墙报（HTML → PDF → 可编辑 PPTX）

**这一节是流水线的起点。** 用户给的通常是一篇（或几篇）论文 + 图 + 数据 + 会议要求，
不是一份现成的 HTML。`01`–`04` 讲"怎么把 HTML 变成逐元素对齐的 PDF/PPTX"，
这里讲"**怎么先把墙报做出来**"：收输入 → 定故事线与面板 → 按墙报口径改写文案 →
处理图表与引用 → 写成满足模板契约的 HTML → 导出三种交付物。

> 只做后一半（已有 HTML，只要转 PPT）也能用：直接跳到 `@references/01-workflow.md`。

## 0. 先收齐输入（缺什么先问，不要猜）

| 类别 | 具体 | 缺了会怎样 |
|---|---|---|
| 内容 | 论文全文或关键章节（PDF/Word/链接）、要上墙的结论 | 文案只能靠猜 → 与图对不上（04-operations §6） |
| 图 | 原始图文件（≥300 dpi 或矢量）；只有论文 PDF 时按 `03` 节渲染取图 | 图糊、裁白边后纵横比错 |
| 数据 | 性能指标/对比数字（进 `.metric` 指标行） | 指标行只能空着或编 |
| 会议要求 | 画布尺寸（mm）、是否给模板、**会议编号规则**、投稿类别 | 尺寸错 → 门禁第 1/6 项必挂；编号框写错 |
| 署名 | 作者顺序、通讯作者标记、单位、基金号 | 署名错是**事故级**问题，必须用户确认 |
| 语言 | 中文 / 英文 / 双语（标题下 `.en` 副标题） | 后期返工 |
| 授权 | 图是否已发表（要不要 permission）、是否含未发表数据/合作者姓名/涉密 | 见 §4，**先问再做** |

## 1. 定"一句话主张"与面板划分（先写提纲，再写 HTML）

1. **一句话主张**：这张墙报要别人记住什么 → 写进标题下的 `.en` 副标题。
2. **3–5 个支撑点** → 每点一个面板；模板是 3 栏 5 面板的契约（`01-workflow` §2）。
3. 面板顺序：**背景/问题 → 方法 → 结果 1..n → 结论 → 展望**（面板号 1..5 与 `.panel-head .num` 对应）。
4. 每个面板固定三件套：**1 张图 + 3–6 条要点 + 1 条小结**（`.note`）。
5. 常见反例（都会被 `40_verify_pptx.py` 或人工一眼看出）：
   把论文摘要整段贴上；一栏塞 12 条要点；图注当正文；同一结论在 3 个面板重复。

## 2. 文案改写规则（墙报 ≠ 论文）

| 规则 | 口径（模板默认字号，900×1200 mm / 3402×4536 px） |
|---|---|
| 一节要点数 | 3–6 条（`li` 27 px，单条 **≤2 行**） |
| 段落文字 | 尽量不用长段；必须成段时用 `p`（27 px，行高 1.38） |
| 小结 | 一句 `.note`（24 px），只描述**本节**的图；跨节引用写"见 Fig. N（panel M）" |
| 标题 | 面板标题 `h2` 35 px + 英文 `.en` 19 px；主标题 76 px，英文副标题 33 px |
| 语气 | 去掉论文腔（"本文/我们"→"该体系/本工作"或直接陈述）；结论用陈述句 |
| 数字 | 每个数字都要能在图上找到出处；图注与图内标注必须一致 |
| 引用 | `[n]` 与正文/图注一一对应；引用列表面板（`.refs`）只列**真正引用**的 |
| 术语 | 首次出现给全称 + 缩写；之后统一用缩写 |

## 3. 图：从文献到上墙

- **取图**：优先向作者要原图；只有论文 PDF 时按 `03` 节按 300 dpi 渲染再裁白边。
- **尺寸**：按 `01-workflow` §2 的内容区可用宽度定宽（左右栏 964 px / 中栏 1064 px），
  高按源图纵横比算；`width`/`height` 必须同时写；改完必须跑
  `python scripts/30_figure_tools.py aspect --html poster.html`。
- **图注**：`Fig. N` + 一句话**结论**（不是"示意图"）；多图合一用"一图两图注"，图号沿用。
- **来源说明**：`.note` 里写清哪些图来自哪篇文献、哪些是本组原始图、哪些数据集未采用
  （授权留痕，见 `00-install` §6）。

## 4. 合规红线（做之前确认，做完留痕）

| 情形 | 做法 |
|---|---|
| 已发表论文插图 | 期刊/出版社通常保留图片版权（**即使你是作者**）→ 走 RightsLink/permission，或换本组未发表原图 |
| 未发表数据 / NDA | 先签授权；交付后按约删除原始数据 |
| 合作者姓名、单位 | 需本人同意后再上墙 |
| 会议 logo / 会标 | 按征稿要求；**接商业单**不要自带他人会标 |
| 字体 | 只写字体名，**不随包分发字体文件**（随 Windows 授权的字体不能转发） |

一句话：**工具无罪，素材和授权才是风险点**。付费墙报交付时把"每张图/每个 logo 的来源与授权"留痕。

## 5. 三种交付物（同一份 HTML 是唯一真源）

| 交付物 | 怎么产出 | 用途 |
|---|---|---|
| `poster.html` | 复制 `templates/poster_template.html` 后改画布/字号/文案（契约见 `01-workflow` §2） | **唯一真源**；浏览器打开即所见，可继续迭代 |
| `poster.pdf` | `10_measure_gate_export.py --pdf`（按画布 mm 打印，单页、无页边距、背景开） | 送印 / 投稿 |
| `poster.pptx` | `20_html2pptx.py` 由 `shapes.json` 生成（文本框 + 图片 + 形状，非图片贴图） | 现场改字/改图 |

顺序固定：**HTML → 门禁 PASS → 导出 PDF 与 PPTX → `40_verify_pptx.py` 验收**。
门禁不过只改 HTML 再重跑，**不要**手工挪 PPT 坐标（那会让 HTML 与 PPT 从此不同源）。

## 6. 交付前清单

- [ ] 门禁 15 项全 PASS（`01-workflow` §3；**跳过一律算失败**，确实不需要时用 `--allow-skip`）
- [ ] `40_verify_pptx.py` PASS（编号居中 / 文本落位 / 图片变形与裁切 / 包结构 / 页尺寸；
      没有可比对的编号要显式 `--no-badge-check`，缺图必须判 FAIL）
- [ ] 三种文件同版本同名；PPTX 在 PowerPoint 里能编辑（文本框可改字，不是贴图）
- [ ] 每轮改动前后都有快照（`50_snapshot.py`），回退路径清楚
- [ ] 图片来源说明、编号框、基金号、通讯作者标记齐全
- [ ] 用户已确认：作者顺序、单位、编号、语言（是否双语）

## 7. 多轮返工怎么办

墙报很少一次过。第二轮之后，真正决定效率的不是排版技巧，而是**接反馈的方式**：
逐条落实并逐条回报、用数字（余量/底边差/页尺寸）代替"改好了"、改前快照、只改一份真源。
具体做法、文案纪律与自我怀疑清单见 `@references/06-field-notes.md`；
如果你改过脚本或换了机器，先用 `scripts/60_pressure_matrix.py --quick` 确认工具链本身没坏
（`@references/07-pressure-matrix.md`）。
