# 02 · HTML → PPTX 映射规则（核心）

目标：PPTX 打开后每个元素都在浏览器里的位置，且文字可编辑。15 条按重要性排序，
`scripts/20_html2pptx.py` 是它们的参考实现。

1. **坐标单位**：`1 CSS px = 9525 EMU`（96 dpi），`1 px = 0.75 pt`，
   幻灯片 `= 目标毫米 × 36000 EMU`。`--slide-mm` 必须等于画布 px 换算的毫米数
   （坐标按 9525 EMU/px 写死，幻灯片按毫米设，不一致会裁右边/下边，脚本会告警）。

2. **文本取"内容盒"，不是边框盒**：
   `x = rect.x + borderLeft + paddingLeft`，`y = rect.y + borderTop + paddingTop`，
   `w/h` 同理减掉 `border+padding`。不做的话 `.note`（8 px 左边色条 + 12 px 内边距）里的文字
   会压在色条上，`li`（`padding-left:28px`）的文字会压在项目符号上。

3. **按段拆成独立文本框**：用 `Range.getClientRects()` 逐段取矩形，block 子元素与 `<br>`
   都是分段落点。否则 `h2` 里的"中文标题 + 英文副标题"会被当成一段不同字号，行距按大字号算，
   英文被推到下一行压住正文。段落矩形是**字体盒**（ascent+descent）而不是 CSS 行盒
   （实测 YaHei：1.14 行高的 h1 行盒 86.6 px、字体盒 100.5 px）：
   `段落高 = (n−1) × line-height + 字体盒高`，垂直修正取**首行**字体盒高。

4. **行距用精确磅值**：`p.line_spacing = Pt(line_height_px × 0.75)`（`spcPts`）。
   不要用倍数——`spcPct` 会被字体自身行高放大，块高与浏览器不一致 → 溢出/重叠。
   `line-height: normal` 时不设。

5. **垂直修正（底对齐 vs 居中）**：浏览器把字体盒居中于行盒，PPT/LO 在精确行距下底对齐 →
   `dy = 首行字体盒高 − line-height`，`textbox.top = 实测字体盒顶 + dy`。

6. **宽度余量按锚定边给**（PPT 字距与浏览器差 1–2%，同一行可能换行）：

   | 对齐 | 宽度 | x 偏移 | 原因 |
   |---|---|---|---|
   | left/start | `w + 6` | 0 | 向右长，左边界不动 |
   | center | `w + 48` | `−24` | 两侧对称长，中心不动 |
   | right | `w + 48` | `−48` | 向左长，右边界不动 |
   | 双向居中徽标（hv） | `w` | 0 | 精确盒 + MIDDLE 锚点，不加高不加宽 |

   居中不给余量 → 指标卡文案多折一行压住数值；居中文案给"向右 +6" → 数字整体右偏 3 px。

7. **编号数字单独采集**（`.num`/`.n` 这类 flex 居中小方块，不在常规文本选择器里）：
   `mode='hv'`，文本框 = 方块本身尺寸（**不加高度余量**），`MIDDLE` 锚点 + `CENTER` 对齐。
   漏采方块是空的；加了高度余量数字会下沉（余量/2）。

8. **flex 直接子元素各自成框**：`display:flex` 的子元素会被块化，文本遍历会把它们粘成一段。
   编号 `[1]` 与正文这种结构要拆成两个文本框，否则 `[1]` 独占一行、正文没有悬挂缩进、与下方 note 重叠。

9. **圆角矩形** `shp.adjustments[0] = min(0.5, radius / min(w,h))`；`/(min/2)` 会让
   50×50 的编号方块变成正圆。**radius == 0 时用普通矩形**（`roundRect` 即使 `adj=0`，
   LibreOffice 渲染的边缘抗锯齿也与矩形不同，会让"本该直角的形状"在逐像素比对里露出来）。

10. **项目符号（`li::before`）**：不是文本节点，几何与颜色都取计算样式
    （`width/height/left/top/background-color/border-radius`），文字用内容盒起点。
    只采集**真的画出来了**的伪元素：`content` 为空/`none`，或宽高为 0（例如原生 `list-style`
    圆点）必须跳过——否则会给每个 `li` 补一个 15×15 假方块再画成主题色，正好盖在原生圆点上。
    **有描边没底色的空心符号要画**（fill 为空 + 描边），纯文字符号（`content:"◆"` 且无尺寸）不画方块；
    采集数 < `li` 数时要提示用户"原生项目符号在 PPT 里不复现"。

11. **字体与行内效果**：每个 run 同时设 **latin / ea / cs** 三处 typeface，值 = 浏览器字体栈
    第一个族（只设 latin 会让中文走别的回退字体 → 字宽不同 → 换行点不同）。`run.size` 已是浏览器
    算好的最终字号，**不要再乘系数**。四类行内效果必须一并搬过去：

    - **上下标**：偏移量按「**同一视觉行**内字体盒基线（`y + 0.8×h`）之差」实测，
      `baseline = −shift / 字号 × 100000`；`|shift| > 0.5 em` 视为测量异常，宁可不设。
      **不要拿整段的基线中位数当基准**：多行段落里只覆盖前几行的 run 会被算成 −9 行的假偏移
      （实测底边偏 281 px、160 个 run 被误加 baseline）。
    - **下划线 / 删除线**：`text-decoration-line` → `underline` / `strike="sngStrike"`。
    - **大小写变换**：`text-transform` 是渲染期变换，要落到文字上（upper / lower / capitalize）。
    - **换行**：`white-space:nowrap` → `word_wrap = False`，否则 PPT 会在浏览器不换行处换行。

12. **图片：`object-fit` 必须真的做出来**（`add_picture` 只按框拉伸，不做裁切）：

    | CSS | 做法 |
    |---|---|
    | 默认 / `fill` | 按实测框拉伸（与 CSS 的拉伸语义一致） |
    | `cover` | 帧 = 实测框，按 `object-position` 算出源图可见区，写进 `srcRect`（`pic.crop_left/top/right/bottom`） |
    | `contain` / `scale-down` | 等比缩放到框内，再按 `object-position` 摆位（帧小于实测框） |

    **不这么做会怎样**：宽高比相差很大的横幅（源图 4:1 放进 8.5:1 的框）会被拉成扁的，
    实测横幅区域与浏览器差 6.4/255（按 `srcRect` 裁切后 0.28/255）。
    `border-radius` 用 `prstGeom roundRect` + `adj = radius/min(w,h)`（等价于 PPT
    "裁剪为形状"），否则 CSS 的圆角图片在 PPT 里是直角。
    `transform: rotate()` 用 `pic.rotation`（帧取**未变换**尺寸，位置取包围盒中心）；
    含 scale/skew 的变换无法表达，只告警，不要假装画对了。

13. **z-order**：面板/卡片底 → 面板标题条 → 边框/项目符号 → 图片 → 文本。
    文本最后画保证不被盖住；图片在文本之前，图注压不到图上。

14. **四条边框都要采，不能用一条代表四条**：CSS 允许单边边框（`.panel-head` 只有
    `border-bottom:3px`、`.note` 只有 `border-left:8px`）。规则：
    - 四边等宽 → 用形状轮廓（`line.width` = 该宽度）；
    - 否则 → 形状只填色，再为每条 `width>0` 的边画一个细矩形（上/右/下/左各一次）。
    只采 `border-top` 会让分隔线整条消失（实测 `.panel-head` 的下边线就这样丢过）。
    **圆角 + `overflow:hidden` 会裁切子元素**：贴角的子元素用 `custGeom` 按父容器圆角逐角还原
    （`prstGeom` 只能四角同半径）；完全落在圆角外的子元素在浏览器里根本看不见 → 不要画；
    部分被裁的只告警（逐角圆角还原不了"裁掉一半"）。
    `border-style: dashed/dotted` → `line.dash_style`（等宽边框用轮廓时可表达）；
    `box-shadow` 无法用形状表达，检测到就告警，别静默丢掉。

15. **段落、可见性、颜色与验证闭环**：一个 HTML 元素 → 1..n 个文本框（按段）。
    **每段要带自己的文字原点 x**：`<dd>`/`<ol>`/`<blockquote>` 的缩进不能丢（实测丢过 24 px）；
    **同一个元素被多个选择器命中时只输出一次**（`<li>` 在 `.note` 里曾被输出两遍）；
    左对齐的"收缩宽度"元素要把可用宽度放宽到父容器内容盒右边界，否则 PPT 会在浏览器不换行处换行；
    名称用 `TXT <前32字>` / `FIG <文件名>`（重名加 `#n` 后缀——同前缀的多个元素与同一图片被多次引用
    都会重名，实测 7 处）；
    `auto_size = NONE`；色值全部来自实测（透明取渐变第一个色停靠点），取不到就不上色，
    **不要回落成写死的主题色**。
    **"-1 = 没有颜色"与"0 = 黑色"必须分开**：`rgb()`/`bgcol()` 解析不到时返回 `-1`，
    下游一律按**存在性**判断（`is not None` / `>= 0`）。用真值判断（`if fill:`）会把
    黑色填充、黑色边框、黑色单边线、黑色项目符号整块丢掉——深色配色的墙报会白字压白底。
    除 `rgb()/rgba()/#hex` 外，计算值可能是 `oklch()/lab()/lch()/color()/color-mix()`：
    交给 canvas 归一化成 sRGB；仍然解析不到就**告警**，不要静默变黑。
    **对齐**：`left/start`、`center`、`right/end`、`justify` 各走各的分支；
    未识别的值按左对齐处理并告警（旧版把所有非 left/center 的值都当右对齐，`justify` 会错排）。
    **正文块元素必须都收进 `CFG.texts`**——漏了 `p`，用 `<p>` 写的正文在 PPT 里会整段消失（实测踩过）；
    `visibility:hidden` / `display:none` 的内容不进 PPT；半透明文字（`color:rgba()` 或祖先
    `opacity`）要按**最近的不透明祖先背景**合成成不透明色，否则 PPT 里会变成实色。
    `PPTX →(LibreOffice) PDF →(pymupdf 150dpi) PNG` 与 HTML 预览 PNG 逐项比对
    编号墨迹中心 / 文本墨迹顶边 / 图片框与裁切 / 包结构 / 页尺寸。任何一项超阈值，先怀疑第 2–9 条。

### 已知的渲染器差异（可接受）

LibreOffice 与 PowerPoint 对"精确行距首行基线"的处理可能差 ±8 px（实测 76 px 大标题处最大
6.4 px）→ 标题块上下留 ≥40 px 余量就不会互相压；**不要**把两行文字排到只差 10 px 的位置上。

### 不要用"看起来没问题"代替判定

- 旋转过的图：`getBoundingClientRect()` 是**旋转后包围盒**，比例天然不等于源图 →
  纵横比审计必须跳过带 `transform` 的图，否则报假"变形"（实测 2.86%）。
- `object-fit:cover/contain`：框比例 ≠ 源图比例是**设计**，不是变形 → 必须真做裁切/等比，
  并在验收里查"是否真的做了"（`srcRect` / 帧尺寸）。
- 图片与 PPTX 对象的对应**不能按序号**：任何一张图被跳过都会让后面全部错位 →
  用对象名（`FIG <文件名>`，重复加 `#n`）配对，配对不上或数量不符就判 FAIL。
